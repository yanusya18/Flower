## Що змінено за кроками

| Крок | Що зроблено | Результат |
|---|---|---|
| 1–2. Базовий аудит | Три запуски на версії з фото «як є» (PNG, без розмірів і lazy) | Performance 84, LCP 4,3 с, CLS 0,033 |
| 3. Стиснення зображень | `npm run images` (скрипт `scripts/optimize-images.mjs`, бібліотека sharp) створює AVIF і WebP кількох ширин. Оригінали не збільшуються | PNG по 181–239 КіБ стали AVIF по 6–12 КіБ (WebP по 8–17 КіБ) |
| 4. Lazy loading | `loading="lazy"` і `decoding="async"` для зображень нижче першого екрана (компонент `Picture`) | Фото «Історія» й «Особливості» не блокують перший екран |
| 5. Розміри зображень | `width` і `height` береться з `images.manifest.json`; `fetchpriority="high"` і без lazy для головного фото | CLS 0,033 → 0 |
| 6. Шрифти | Шрифти розміщено локально (`public/fonts`): Lobster (кирилиця, латиниця) і Baskervville SC (латиниця), лише накреслення 400; `font-display: swap`; preload двох шрифтів першого екрана | Немає запитів до сторонніх серверів, FCP 1,8 → 1,5 с |
| 7. Скрипти | Єдиний скрипт `type="module"` вже відкладений за замовчуванням, атрибут `defer` для модулів не потрібен | Без змін (див. примітку нижче) |
| 8. Повторний аудит | Три запуски на новій збірці | Performance 97 |

### Що дало найбільший ефект

Найбільше дало стиснення головного зображення: це елемент LCP, і його вага впала зі 181 КіБ (PNG) до 5,9 КіБ (AVIF). Загальний обсяг даних зменшився на 76 % (769 → 188 КіБ), майже все за рахунок зображень. Додатковий ефект дало прибирання зсуву макета через `width`/`height`.

## Примітки

- **Скрипти (крок 7).** Vite підключає `<script type="module">`, а модулі виконуються після розбору HTML, тобто так само, як `defer`. Невикористаний код у проєкті відсутній. Lighthouse усе ще показує ~35 КіБ невикористаного JavaScript: це внутрішня частина `react-dom`, яку не можна прибрати, не замінивши бібліотеку (наприклад, на Preact).
- **Шрифти.** У базовій версії використовувався Google Fonts з `display=swap` та лише накресленнями 400, тому змінилося саме джерело: локальні файли без додаткових з'єднань. У моєму тесті Google Fonts імітовано двома локальними серверами на різних портах, тому реальний виграш у вашому браузері може бути більшим.
- **Кешування.** Lighthouse ще радить довший термін кешування для файлів зі `public/` (шрифти, зображення). Це налаштовується на хостингу, а не в репозиторії.

## Умови лабораторних замірів

- Lighthouse CLI 13.5.0, мобільна емуляція, симульоване тротлінгове з'єднання (за замовчуванням), headless Chromium на Linux.
- Збірка віддавалась локальним сервером зі стисненням gzip і довгим кешем для файлів із хешем. API-сервер (`server/`) був запущений.
- Результати Lighthouse коливаються від запуску до запуску, тому для кожної версії зроблено по три запуски й взято медіанний.
- Фото на сторінці це тимчасові зображення з вашого мудборду (`src/assets/photos-src`). Для фінальної версії замініть їх власними або ліцензійними фото й запустіть `npm run images`.

## Як повторити

```bash
npm run images   # стиснути зображення з src/assets/photos-src
npm run build
npm run preview  # у другому терміналі: cd server && npm start
```
Потім відкрийте адресу з `npm run preview` у Chrome (інкогніто) і запустіть Lighthouse.
