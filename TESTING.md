# Тестування проєкту Flower

Практичне заняття № 25. Тестування, DevTools, виправлення помилок.

## Середовище й обмеження

- Збірка `npm run build` + локальний сервер, запущений API (`server/`), Chromium (Playwright), емуляція пристроїв через розмір вікна.
- Тест-кейси виконані **автоматизованим скриптом**, а не вручну. Стовпець «Ручна перевірка» залишено порожнім: пройдіть кейси у своєму Chrome й позначте результат.
- **Firefox і Safari не запускались**: у середовищі, де проводились перевірки, їх не вдалося встановити. Замість цього зроблено лише статичну перевірку CSS (розділ 5). Повноцінне порівняння в іншому браузері треба виконати самостійно.

## 2. Console

- Збірка (`npm run preview`): помилок і попереджень немає.
- Режим розробки (`npm run dev`): помилок немає. У Network видно один запит `/api/projects` зі статусом `ERR_ABORTED`. Це не дефект (див. «Спостереження»).
- Сервер вимкнено: одна помилка `ERR_CONNECTION_REFUSED`, яку пише сам браузер. Застосунок показує зрозуміле повідомлення й кнопку повторної спроби.

## 3. Network

- Запитів із 404 або 500 немає (перевірено у збірці, API запущено).
- Найповільніший ресурс: `baskervville-sc-latin-400.woff2` (23 КБ, ~314 мс у лабораторних умовах без тротлінгу). Шрифт використовується лише для невеликих підписів, а `font-display: swap` не блокує показ тексту, тому це прийнято без змін.
- Решта запитів (JS 71 КБ, CSS 3 КБ, API) виконуються менш ніж за 50 мс.

## 5. Інший браузер

**Не виконано** (Firefox і Safari недоступні). Що зроблено натомість: статична перевірка CSS інструментом `doiuse` для Firefox ≥ 115, Safari ≥ 15, Chrome ≥ 110.

Результат: єдині зауваження стосуються Safari 15.0–15.3 (і iOS Safari тих версій): немає `scroll-behavior` (плавне прокручування просто не спрацює) і `:focus-visible` (там діє стандартна рамка фокуса). Для сучасних версій проблем не виявлено. Фото віддаються через `<picture>` з AVIF і запасним WebP, тож старіші Safari без AVIF отримають WebP.

## 7. Спостереження (не дефекти)

- У режимі розробки React StrictMode запускає ефект двічі, тому перший запит до API скасовується (`AbortController`) і виглядає в Network як `ERR_ABORTED`. У збірці такого немає.
- Після успішного надсилання форма не очищається: повідомлення «Дякуємо!» лишається, доки користувач не змінить поле. Можна очищати поля, якщо це потрібно за вимогами.
- Лічильники вподобань живуть лише в пам'яті сторінки й обнуляються після перезавантаження. Це відповідає завданню (стан у `useState`).

## 8. Регресія

Після виправлень повторно виконано: усі 15 тест-кейсів (15 із 15), юніт-тести (4 на фронтенді, 6 на сервері), наскрізний тест із API (форма, фільтр, стан «сервер вимкнено») та перевірку контрасту й клавіатури з Практичного 24 (axe-core без порушень, 24 зупинки Tab). Нових проблем не виявлено.

## 9. Додаткове завдання

Не виконано: для нього потрібен проєкт одногрупника.

## Як повторити вручну

1. Запустіть `cd server && npm start` і `npm run build && npm run preview`.
2. Відкрийте сторінку, натисніть F12. Вкладка **Console**: перезавантажте сторінку й перевірте повідомлення. Вкладка **Network**: перезавантажте, відсортуйте за статусом і часом.
3. Натисніть значок пристроїв (Ctrl+Shift+M) і перевірте ширини 320, 390, 768, 1280.
4. Пройдіть кожен кейс із таблиці й позначте результат у стовпці «Ручна перевірка».
